提取失败的常见原因

先别怀疑人生

  1. 模式选错：直接替换和 HPP 的载波数量不同（66 vs 88）。
  2. 密钥错：读出来会是一串“很像乱码”的十六进制。
  3. 音频被改过：转 MP3、裁剪、重采样、降噪都会破坏帧对齐。
  4. 不是本站生成：当前只认这条 EnCodec 24 kHz / L0 链路。

读出来不报错，不等于读对。填“期望口令”才能自动比对。

05 · 失败模式

现在会怎么坏

单比特错失败样本里最常见的是 16 bit 中错 1 位（如 1391 → 1390）。Viterbi 已经收敛到邻域，差的是最后一格。
消息依赖有些 16 bit 组合在这段音频上结构性难解：raw 停在 0.74 左右，换 12 种置换也救不回来，最后降级为 direct。
短音频帧数少于 P 时直接不可行（示例里 2.09 s 那条只有 157 帧，P=160 装不下）；P 被压小后可行解也变窄。
链路外MP3、重采样、裁剪、降噪、微信语音都会破坏帧对齐。当前只对同一条 EnCodec 24 kHz / L0 链路负责。

06 · 写论文时的措辞

能写与不能写

可以写

  • 同链路 PCM16 回读后 16 bit 消息可恢复（direct 100%，HPP 97.5%，独立复现 102/105）。
  • 直接换索引改变边际分布，简单分析器 AUC 0.89–0.92。
  • HPP 使 token 层多重集严格不变，直方图 AUC 降至 0.598。
  • HPP 的残余风险仍在波形层（LFCC 0.574、Nes2Net 0.645）。

不能写

  • 不可检测 / 统计不可区分。
  • 密码学安全（错钥 50% 只是映射性质）。
  • 跨 codec、跨平台鲁棒。
  • 高容量或实时可部署。
